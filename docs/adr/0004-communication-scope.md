# ADR-0004: 통신 범위(scope) 모델

- 상태: Accepted
- 관련 목표: G5
- 작성일: 2026-09-19

## 질문

무분별한 확장을 막기 위해, 어떤 세션이 어떤 세션을 보고 메시지를 보낼 수 있는지를 어떤 단위로 제한하는가?

## 맥락

- Claude의 현재 범위는 '같은 CONFIG_DIR + 같은 uid'다. 프로젝트 개념은 없다.
- Orca는 Run/워크트리/그룹 주소(`@worktree:<id>`, `@claude` 등)를 쓴다(orchestration 가이드, `docs/references/orca.md` 6절).
- INTENT.md는 이것을 확정 사항이 아니라 토론 대상으로 명시한다.
- Claude Code에는 수신 정책 설정이 이미 있다(`docs/references/README.md` 2.3절).
  - `crossSessionInbound`: `accept`/`hold`/`refuse`. 값이 없으면 권한 모드가 같을 때만 자동 전달한다.
  - 우선순위: 관리 정책 > 플래그 > 사용자 설정. 저장소 설정은 더 엄격하게만 바꿀 수 있다.
  - `isolatePeerMachines`: 다른 머신으로 보낼 때 매번 승인을 받는다.
  - 두 설정은 공식 문서(`code.claude.com/docs/en/settings`)에 있는 공개 기능이다.
  - 모드 동등성에 쓰는 `from-mode`는 발신자가 봉투에 스스로 적는 값이다. 인증되지 않으므로 범위 제어의 보안 근거로 쓸 수 없다.

- 범위 정책을 한 번의 핸드셰이크로 "신뢰 관계"로 굳히고 그 관계가 유효할 때만 메시지를 허용하는 방식은 ADR-0009에서 다룬다(실험 설계 `docs/spikes/S8-handshake-plan.md`).
- **비교 실측(S9)**: cc-peer default front는 `~/.claude/sessions`에 있는 Claude 세션을 그 세션의 동의 없이 메시에 올렸다. 범위 정책은 메시지 시점뿐 아니라 세션 편입 시점에도 적용돼야 한다. 같은 실험에서 cc-peer가 기본값으로 `from-mode=bypass`를 주장해, Claude 세션이 아닌 node 프로세스의 메시지가 bypass 수신 세션에서 곧바로 실행됐다.

## 선택지

### A. 프로젝트 정책 파일

- 방식: 저장소에 `.agent-mesh.toml` 같은 허용 목록을 둔다
- 장점: 저장소와 함께 버전 관리
- 단점: 저장소 밖의 세션(홈 디렉터리 작업 등) 처리가 애매함

### B. 명명된 그룹

- 방식: 세션이 시작할 때 그룹에 가입하고, 같은 그룹 안에서만 통신한다
- 장점: 프로젝트 경계와 독립적
- 단점: 가입 절차가 필요

### D. Claude 네이티브 정책 확장

- 방식: 수신 측 정책은 `crossSessionInbound` 의미(accept/hold/refuse, 모드 동등성, 저장소는 강화만)를 그대로 쓴다. Codex 수신 어댑터에도 같은 규칙을 적용한다. 송신 측 범위(누구에게 보일지)만 새로 정의한다
- 장점: 사용자가 이미 아는 설정 체계와 일관된다. Claude 쪽은 추가 구현이 없다
- 단점: 비공개 기능의 의미에 의존한다. 송신 측 범위는 여전히 별도 설계가 필요하다

### C. 제한 없음 + 수신 측 거부

- 방식: 모두 보이되 수신 측 정책으로 거부한다
- 장점: 단순함
- 단점: 목록이 폭증하고 기본값이 느슨함

## 결정

**기본 프로젝트 + 이름 붙인 프로젝트(B의 변형)를 택한다**(사용자 결정 2026-09-20·21, xsm v0.1로 구현).

- **기본 프로젝트.** 모든 세션은 시작한 디렉터리의 프로젝트에 속한다. git 저장소면 `repo:<이름>`, 아니면 `dir:<폴더>`다. 같은 기본 프로젝트끼리는 설정 없이 통신한다.
- **이름 붙인 프로젝트.** `xsm join <이름>`(`/xsm join`, Codex `$xsm join`)으로 폴더(저장소 루트) 단위로 가입한다. 기본 프로젝트에 더하는 가입이다. 두 폴더가 모두 같은 이름에 가입해야 열린다. 탈퇴(`leave`)할 때까지 유지된다. 손으로 쓴 범위(`config.json`의 `scopes`)는 그대로 쓸 수 있고, 같은 이름으로 가입하는 것은 거부한다.
- **검사 지점.** 보내기 전과 받는 훅, 두 곳에서 검사한다. 판정은 현재 구성원 경로로 하고, 이름은 표시용이다.
- **목록.** 기본은 이 폴더와 통신할 수 있는 살아 있는 세션만 보인다. `-a`는 전부 보인다.
- **reach(2026-09-28 추가).** 떠 있는 세션 하나와, 다른 폴더(그 git 저장소, 없으면 그 폴더)에서 시작한 세션들 사이만 양방향으로 연다. scope id는 `reach:<ref>`다. 넓히는 일이라 사람만 허락한다(MCP `xsm_reach` 양식, 또는 터미널 `xsm reach <폴더> --session ref:…`). 거두기는 누구나 한다. reach는 그 세션의 한 번의 실행에 묶인다: 허락할 때 `runtime`·`home`·`session_id`와 `pid`·`lstart`를 적고, 이 모두가 맞는 세션에만 적용한다. `ref`만으로 맞추면 24비트 `ref`가 겹친 다른 세션에 열리고, 같은 session id를 새 pid로 재개(`claude --resume`)한 세션에 매시간 정리 전까지 다시 열렸다(2026-09-28 적대적 검토). 그 세션의 `SessionEnd` 훅이 reach를 지우고(훅이 밝힌 홈이 포인터의 홈과 다르면 다른 세션의 인사이므로 아무것도 하지 않는다, 2026-09-28), 인사 없이 끝나거나 재개로 세대가 바뀐 경우는 정리가 지운다. 그 세션의 같은 프로젝트 동료와 다른 폴더에는 열리지 않는다. 가입과 달리 상대 폴더 쪽 동의를 따로 받지 않는다: 두 폴더의 주인이 같은 사람이고, 그 사람이 승인한다.
- **link(2026-09-28 추가).** 두 프로젝트 폴더(각각 git 루트, 없으면 그 폴더)를 한쪽에서 한 번 이으면, 양쪽 폴더 아래에서 시작한 세션들이 양방향으로 `link:<이름>+<이름>` scope로 통한다. 다른 폴더를 잇는 기본 방법이다. `config.json`의 `links`에 적고, 세션에 묶이지 않으며 `xsm unlink`로 지울 때까지 남는다. 넓히는 일이라 사람만 만든다(터미널, 또는 세션에 직접 입력한 명령). 지우기는 누구나 한다. 이름 붙인 프로젝트는 여러 폴더를 한 묶음으로 둘 때 쓰고, 각 폴더가 가입하는 규칙은 그대로다.
- **입력한 명령이 곧 동의(2026-09-28 추가).** 사람이 세션에 직접 입력한 `/xsm link|join|leave|reach <대상>`(Codex `$xsm …`)을 훅이 그 세션의 동의로 적어 둔다(`~/.xsm/asked/<ref>.json`, 10분, 한 번, 같은 동사와 같은 대상에만). Claude는 `UserPromptExpansion` 훅(사람이 입력한 슬래시 명령에만 온다)에서, Codex는 `UserPromptSubmit` 훅에서 `$xsm <동사>`로 시작하고 xsm 봉투·헤더가 아닌 프롬프트로 기록한다. 이 동의가 있으면 에이전트가 실행한 CLI도 통과하고, MCP 도구도 양식 없이 진행한다. 동의가 없을 때만 양식으로 묻는다. 피어 메시지와 xsm 워커의 프롬프트는 동의가 되지 않는다. 남는 한계: Codex에서는 `codex queue`를 돌릴 수 있는 같은 OS 사용자의 프로세스가 `$xsm link …`로 시작하는 항목을 넣어 동의를 위조할 수 있다. 경계는 uid이고 동의 기록은 보안 장치가 아니다(ADR-0009). 세션 입력창에 글자를 넣을 수 있는 프로세스는 그 세션의 양식에도 답할 수 있으므로, 이 한계는 양식 방식에도 똑같이 있다. 자세한 규칙은 `docs/xsm/PROTOCOL.md` 5.3.3.
- **워커와 부모(2026-09-28 추가).** 워커와 그 워커를 띄운 세션은 범위와 관계없이 `worker:<이름>` scope로 통한다. 범위 밖 폴더의 워커는 사람이 허가했을 때만 뜨므로(ADR-0010) 이 짝의 동의는 이미 있다. 이 예외가 없을 때는 허가받고 뜬 워커가 과제를 받지 못했다.
- **D(네이티브 정책).** Claude 수신 정책(`crossSessionInbound`)은 그대로 두고, xsm은 보류 여부를 예보만 한다. xsm이 띄운 Claude 워커만 `--settings`로 `accept`를 받는다.

기각: A(저장소 안 정책 파일. 저장소 밖 세션을 다루기 어렵다), C(제한 없음).
